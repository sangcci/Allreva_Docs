# 설계 결정 기록

이 폴더에는 큰 변경을 검토한 과정과 확정된 결론을 남긴다.

- `rfc/active/`: 검토 중인 제안
- `rfc/completed/`: 결론이 난 RFC
- `adr/`: 확정된 결정

## RFC가 필요한 경우

아키텍처, API 계약, DB 스키마, CI/CD·운영 방식, 사용자 흐름의 경계가 바뀌면 RFC를 작성한다. 성능 개선이나 복잡한 기능은 선택지 비교가 필요한 경우에만 작성한다.

작은 버그 수정, 테스트 보강, 구현 범위가 명확한 작업에는 RFC가 필요하지 않다.

## RFC에서 ADR까지

1. Issue에서 문제와 완료 조건을 정한다.
2. RFC에서 선택지와 권장안을 검토한다.
3. 결론이 나면 RFC를 `rfc/completed/`로 옮긴다.
4. ADR에 최종 결정, 이유, 감수한 점, 영향을 짧게 남긴다.
5. 구현 PR에는 관련 Issue와 공식 문서 링크를 남긴다.

RFC는 검토 과정을 보존하고, ADR은 현재 기준의 결론을 빠르게 찾기 위한 문서다. 결정이 바뀌면 기존 ADR을 고쳐 쓰지 않고 상태를 `대체됨`으로 바꾼 뒤 새 ADR을 만든다.
