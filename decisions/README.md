# 설계 결정 기록

이 폴더에는 현재 기준이 되는 중요한 결정과 이전 검토 기록을 남긴다.

- `adr/`: 오래 영향을 주는 중요한 아키텍처, 운영, 정책 결정
- `templates/adr.md`: ADR 작성 양식
- `rfc/`: 이전 workflow에서 작성한 보존 기록. 새 workflow artifact로 만들거나 연결하지 않는다.

ADR 파일명은 `ADR-001-의미-있는-slug.md` 형식으로 쓴다. Issue와 PR 번호는 작업 추적용이므로 문서 식별자와 맞추지 않고, 문서 상단의 관련 자료 링크로 연결한다.

## Issue와 ADR 범위

Research, 사용자와의 대화, 승인된 plan 뒤에 Issue를 만든다. Issue는 개발 workflow 진입 전에 필요한 이유, 이번 범위, 완료 조건을 남긴다.

ADR은 여러 작업에 오래 영향을 주는 중요한 아키텍처, 운영 또는 정책 결정을 확정할 때만 작성한다. 단순 작업은 Issue만으로 완료할 수 있다.

## Issue에서 결정까지

1. Research, 사용자와의 대화, 승인된 plan 뒤 Issue에서 문제, 범위, 완료 조건을 정한다.
2. 중요한 아키텍처, 운영 또는 정책 결정을 확정하면 ADR에 최종 결정, 이유, 감수한 점, 영향을 짧게 남긴다.
3. 구현 PR에는 관련 Issue와 공식 문서 링크를 남긴다.

ADR은 중요한 현재 기준의 결론을 빠르게 찾기 위한 문서다. `rfc/`의 기록은 당시 검토와 검증 근거를 보존하지만 현재 workflow 기준이 아니다.

ADR은 결정 상태와 적용 상태를 나눈다. 결정 상태는 `채택됨`, `대체됨`, `폐기됨`이고, 적용 상태는 `미적용`, `적용 중`, `운영 검증 완료`, `적용 보류`다. 운영 검증이 보류되거나 다른 문제가 생겨도 결정이 유효하면 적용 상태만 바꾼다. 결정이 바뀌면 기존 ADR을 고쳐 쓰지 않고 `대체됨`으로 바꾼 뒤 새 ADR을 만든다. 일부 규칙만 바뀌면 후속 ADR과 바뀐 범위, 계속 적용하는 범위를 함께 적는다.
