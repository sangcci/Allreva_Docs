# PR 템플릿

PR은 코드 변경을 설명하는 장소이면서, 리뷰어가 변경 이유와 검증 수준을 빠르게 판단하는 기록이다. 공식 설계 문서를 복사하지 않는다. 관련 내용은 Allreva_Docs의 문서 링크로 연결한다.

```md
## 왜 바꾸는가
<!-- 이 PR이 해결하려는 문제나 변경 이유를 한두 문장으로 적습니다. -->

## 무엇이 달라지는가
<!-- 사용자, API, 데이터, 운영 방식 중 무엇이 어떻게 달라지는지 적습니다. -->
-

## 확인한 내용
<!-- 실행한 테스트 명령, CI 결과, 수동 확인, 재현 실험을 적습니다. -->
-

## 아직 확인하지 못한 내용
<!-- 없다면 '없음'이라고 적습니다. 있다면 이유와 남은 위험을 짧게 적습니다. -->
- 없음

## 문서
<!-- 공식 기준 문서는 Allreva_Docs입니다. 문서가 바뀌었으면 해당 Issue 또는 PR 링크만 남깁니다. -->
- 기준 문서: 없음

## 관련 Issue
- closes #

## 리뷰 시 봐줄 부분 (선택)
<!-- 설계 선택, 트레이드오프, 특히 확인이 필요한 부분이 있으면 적습니다. -->
```

## 작성 예시

```md
## 왜 바꾸는가
브라우저 환경과 배포 환경에서 RefreshToken 쿠키 옵션이 달라져, 코드를 수정하지 않고 설정으로 조정할 수 있어야 한다.

## 무엇이 달라지는가
- RefreshToken 쿠키의 `Secure`, `SameSite` 옵션을 profile별 설정으로 분리한다.

## 확인한 내용
- `./gradlew test` 통과
- local profile에서 로그인 응답의 `Set-Cookie` 헤더 확인

## 아직 확인하지 못한 내용
- staging 환경의 실제 HTTPS 쿠키 동작은 배포 후 확인이 필요하다.

## 문서
- 기준 문서: Allreva_Docs#12

## 관련 Issue
- closes #107
```
