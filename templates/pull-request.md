# PR 템플릿

PR은 리뷰어가 코드만 보고 추측하지 않도록, 변경한 이유와 확인한 범위를 짧게 설명하는 기록이다. 공식 설계 문서를 복사하지 않고, 관련 내용은 Allreva_Docs 문서 링크로 연결한다.

작은 변경은 모든 항목을 길게 채우지 않아도 된다. 실제로 바뀐 점과 확인한 내용만 사실대로 적는다.

```md
## 배경
<!-- 이 PR이 필요한 이유를 한두 문장으로 적습니다. 자세한 배경은 Issue 또는 RFC 링크로 넘깁니다. -->

## 이번 PR에서 한 일
<!-- 바뀐 동작이나 문서를 짧게 적습니다. -->
-

## 확인한 내용
<!-- 실행한 테스트 명령, CI 결과, 수동 확인, 재현 실험을 적습니다. -->
-

## 남은 확인 사항
<!-- 없다면 '없음'이라고 적습니다. 있다면 이유와 남은 위험을 짧게 적습니다. -->
- 없음

## 관련 문서
<!-- 공식 기준 문서가 바뀌었으면 해당 Issue 또는 PR 링크만 남깁니다. -->
- 기준 문서: 없음

## 관련 Issue
- closes #

## 리뷰 시 봐줄 부분 (선택)
<!-- 설계 선택, 트레이드오프, 특히 확인이 필요한 부분이 있으면 적습니다. -->
```

## 작성 예시

```md
## 배경
브라우저 환경과 배포 환경에서 RefreshToken 쿠키 옵션이 달라, 코드를 수정하지 않고 설정으로 조정할 수 있어야 한다.

## 이번 PR에서 한 일
- RefreshToken 쿠키의 `Secure`, `SameSite` 옵션을 profile별 설정으로 분리했다.

## 확인한 내용
- `./gradlew test` 통과
- local profile에서 로그인 응답의 `Set-Cookie` 헤더 확인

## 남은 확인 사항
- staging 환경의 실제 HTTPS 쿠키 동작은 배포 후 확인이 필요하다.

## 관련 문서
- 기준 문서: Allreva_Docs#12

## 관련 Issue
- closes #107
```
