# 공통 작업 Issue 템플릿

이 양식은 리팩터링, 테스트, 문서, CI/CD, 운영 정리처럼 사용자 기능 추가나 버그 수정으로 분류하기 어려운 작업에 사용한다.

GitHub Form에서는 작업 유형을 선택한다. Issue를 만들기 전 제목 접두사도 선택한 유형에 맞게 직접 바꾼다. 예를 들어 테스트 작업은 `[TEST] 테스트 설명`처럼 쓴다.

```md
## 작업 유형
<!-- REFACTOR / TEST / DOCS / CI / CHORE / PERF 중 하나를 고릅니다. -->

## 무엇을 정리하거나 바꾸는가
<!-- 현재 상태와 바꾸려는 내용을 짧게 적습니다. -->

## 작업 배경
<!-- 방치했을 때 생기는 문제나, 이 작업이 필요한 이유를 적습니다. -->

## 이번에 하는 일
-

## 완료 조건
<!-- 확인 가능한 조건을 1~3개 적습니다. -->
- [ ]

## 구현 메모 (선택)
<!-- 제약, 검토할 선택지, 관련 RFC가 있으면 적습니다. -->

## 관련 자료
<!-- 관련 Issue, PR, 문서, 코드 경로를 적습니다. -->
-
```

## 작성 예시

```md
## 작업 유형
REFACTOR

## 무엇을 정리하거나 바꾸는가
Auth와 Member 서비스에 섞인 회원 상태 조회 책임을 분리한다.

## 작업 배경
로그인과 회원 상태 변경이 같은 Service에 섞여 있어 변경 범위를 파악하기 어렵다.

## 이번에 하는 일
- 회원 상태 조회 진입점을 분리한다.
- 호출하는 API와 테스트를 정리한다.

## 완료 조건
- [ ] 로그인 흐름과 회원 상태 조회의 책임이 별도 진입점으로 나뉜다.
- [ ] 관련 단위 또는 통합 테스트가 통과한다.

## 관련 자료
- #108
```
