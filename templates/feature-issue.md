# 기능 Issue 템플릿

이 양식은 새 기능, 개선, 리팩터링처럼 “무엇을 바꾸고 어디까지 끝낼지”를 먼저 합의해야 하는 작업에 사용한다. 구현 방법을 이미 알고 있더라도, 문제와 완료 조건보다 앞에 두지 않는다.

```md
## 한 줄 설명
<!-- 무엇을 바꾸는지 한 문장으로 적습니다. -->

## 작업 배경
<!-- 지금 불편한 점, 해결하려는 문제, 기대하는 변화를 적습니다. -->

## 이번에 하는 일
<!-- 이 Issue 안에서 다룰 범위를 적습니다. -->
-

## 이번에는 하지 않는 일 (선택)
<!-- 범위를 넓히지 않기 위해 제외할 내용이 있을 때만 적습니다. -->
-

## 완료 조건
<!-- 확인 가능한 조건을 1~3개 적습니다. 구현 항목을 길게 나열하지 않습니다. -->
- [ ]

## 구현 메모 (선택)
<!-- 이미 알고 있는 제약, 검토할 선택지, 관련 RFC가 있으면 적습니다. 설계가 필요하면 RFC 링크를 남깁니다. -->

## 관련 자료
<!-- 관련 Issue, PR, RFC, ADR, 코드 경로를 적습니다. 없으면 생략합니다. -->
-
```

## 작성 예시

```md
## 한 줄 설명
로그인 응답에서 온보딩 완료 여부를 함께 반환한다.

## 작업 배경
클라이언트는 로그인 후 별도 조회 없이 온보딩 화면으로 보낼지 결정해야 한다.

## 이번에 하는 일
- 로그인 응답에 온보딩 완료 여부를 추가한다.
- 기존 로그인 흐름이 깨지지 않는지 테스트한다.

## 이번에는 하지 않는 일
- 온보딩 화면의 UI 변경
- 온보딩 단계 자체의 변경

## 완료 조건
- [ ] 온보딩을 마친 회원과 마치지 않은 회원의 응답 값이 다르게 반환된다.
- [ ] 기존 로그인 통합 테스트가 통과한다.

## 관련 자료
- #106
```
