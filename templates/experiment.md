# 실험 기록 템플릿

이 양식은 성능, 배포, 장애 재현, 동시성처럼 결과를 실제로 확인해야 하는 작업에 사용한다. 결론만 적지 않고, 같은 조건에서 다시 확인할 수 있는 근거를 남긴다.

```md
# 실험: 제목

> 상태: 진행 중 | 완료
> 실험일: YYYY-MM-DD
> 관련 Issue: #번호 또는 없음
> 관련 RFC / ADR: 링크 또는 없음

## 가설
<!-- 무엇을 확인하려는지, 어떤 결과를 예상하는지 적습니다. -->

## 재현 조건
### 환경
<!-- 코드 버전, 실행 환경, 의존 서비스 버전, 리소스 설정을 적습니다. -->

### 입력과 절차
<!-- 요청 수, 동시 사용자 수, 실행 명령, 장애 주입 방법처럼 같은 실험을 다시 할 수 있는 정보를 적습니다. -->

## 측정 항목
<!-- 무엇을 숫자로 판단할지와 측정 방법을 적습니다. -->
-

## 결과
<!-- 표나 그래프로 결과를 적습니다. 개선 전후를 비교했다면 같은 조건인지 함께 적습니다. -->

## 해석
<!-- 결과가 가설을 지지하는지, 그렇지 않다면 무엇을 알게 됐는지 적습니다. -->

## 한계
<!-- 이 실험으로 말할 수 없는 점, 실제 운영과 다른 조건을 적습니다. -->

## 원본 자료
<!-- 재현 스크립트, 설정, 원본 결과, 이미지가 있는 저장소 경로를 적습니다. 민감정보는 제거합니다. -->
-
```

## 자료 보존 기준

실험 문서와 함께 스크립트, 설정, 작은 원본 결과, 실행 계획, 스크린샷을 최대한 같은 저장소에 남긴다. 대용량 로그나 결과도 우선 보존하되, Git 관리가 어려워지면 별도 저장 방식을 검토한다. API key, 토큰, 쿠키, 개인정보, 운영 서버 주소는 기록하지 않는다.
