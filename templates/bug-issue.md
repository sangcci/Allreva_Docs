# 버그 Issue 템플릿

이 양식은 이미 기대한 동작이 정해져 있고, 실제 결과가 다른 경우에 사용한다. 수정 방법보다 재현 조건과 관찰한 결과를 먼저 남긴다.

```md
## 문제 요약
<!-- 어떤 상황에서 무엇이 잘못되는지 한 문장으로 적습니다. -->

## 재현 방법
<!-- 다른 사람이 같은 결과를 확인할 수 있게 순서대로 적습니다. 재현이 어려우면 관찰한 조건을 적습니다. -->
1.
2.
3.

## 기대한 동작
<!-- 정상이라면 어떤 결과가 나와야 하는지 적습니다. -->

## 실제 동작
<!-- 실제로 본 응답, 화면, 로그, 데이터 변화를 적습니다. -->

## 영향 범위 (선택)
<!-- 영향을 받는 사용자, 기능, 환경이 있으면 적습니다. -->

## 완료 조건
<!-- 수정 후 무엇을 확인해야 닫을 수 있는지 적습니다. -->
- [ ]

## 근거 자료 (선택)
<!-- 로그, 스크린샷, 대시보드, 관련 PR 또는 코드 경로를 적습니다. 민감정보는 지웁니다. -->
-
```

## 작성 예시

```md
## 문제 요약
KOPIS 동기화가 실패해도 배치가 성공한 것처럼 종료된다.

## 재현 방법
1. KOPIS API가 500을 반환하도록 stub을 설정한다.
2. 공연 동기화 배치를 실행한다.
3. 배치 종료 상태와 오류 로그를 확인한다.

## 기대한 동작
외부 API 오류가 발생하면 배치 실패를 알 수 있어야 한다.

## 실제 동작
배치는 성공으로 종료되고, 동기화 실패 건수도 남지 않는다.

## 완료 조건
- [ ] KOPIS API 오류가 발생하면 배치 실행 결과에서 실패를 확인할 수 있다.
- [ ] 실패 상황을 다루는 테스트가 추가된다.
```
