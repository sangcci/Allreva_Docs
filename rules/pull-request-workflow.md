# PR 작성과 문서 연결 기준

PR은 리뷰어가 코드만 보고 추측하지 않도록, 변경 이유와 검증 범위를 짧게 설명하는 기록이다. 모든 PR에는 한두 문장의 변경 이유와 검증 결과를 남긴다.

## PR에 적는 내용

- 왜 바꾸는가: 이 PR이 해결하려는 문제 또는 변경 이유
- 무엇이 달라지는가: 사용자, API, 데이터, 운영 방식에 생기는 변화
- 확인한 내용: 실행한 명령, CI, 수동 확인, 재현 실험
- 아직 확인하지 못한 내용: 없으면 `없음`, 있으면 이유와 남은 위험
- 문서: 관련 공식 문서가 바뀌었을 때 Allreva_Docs Issue 또는 PR 링크

## 문서 연결 방식

공식 지식의 기준은 Allreva_Docs다. 코드 PR은 설계 문서 내용을 복사하지 않고, 필요할 때 기준 문서 링크 한 줄만 남긴다.

```md
## 문서
- 기준 문서: Allreva_Docs#12
```

문서 변경이 없다면 아래처럼 적는다.

```md
## 문서
- 기준 문서: 없음
```

중앙 Docs의 문서가 바뀌었다고 BE·FE의 `AGENTS.md`나 Skill을 항상 바꾸지는 않는다. 문서 구조, 항상 지켜야 할 규칙, 반복 실행 절차처럼 Agent의 탐색이나 실행 방식이 달라질 때만 로컬 Agent 문서를 함께 갱신한다.
